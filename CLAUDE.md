# todolist

A multi-tenant todolist app that humans and AI agents share. Features: `README.md`.
Stack, domain model and rules: `DECISIONS.md` (it wins over personal preference).

## Layout

- `src/todolist/`: backend package (`app.py` has the `create_app()` factory, `config.py` the
  `Settings`, `db.py` the SQLAlchemy `Base`, mixins, engine and `get_session`, `models/` the ORM models,
  `services/` the domain logic, `permissions.py` the permission service, `principals.py` the `Principal` actor type, `api/` the routers under `/api`, `auth.py` the session helpers and
  `current_user`, `google.py` the Google OpenID Connect client, `errors.py` the API errors,
  `mcp_server/` the MCP server at `/mcp`)
- `migrations/`: Alembic environment and `versions/`
- `docker-compose.yml`: PostgreSQL 18 on host port 5435 with the databases `todolist`, `todolist_test`
  and `todolist_e2e`
- `tests/`: pytest tests
- `frontend/`: the React single-page app (Vite, TypeScript strict, React Router, Tailwind CSS 4, npm);
  `frontend/e2e/` holds the Playwright specs

## Run

```sh
uv sync
cp .env.example .env   # once
docker compose up -d   # PostgreSQL; wait until `docker compose ps` shows "healthy"
uv run alembic upgrade head
uv run uvicorn todolist.app:create_app --factory --reload
```

Health check: `GET http://localhost:8000/healthz`.

To sign in locally without Google, set `DEV_LOGIN=true` in `.env` and
`POST /api/auth/dev-login {"email": ..., "name": ...}`. It is off by default and must stay off
in production (the app refuses to start with it there).

## Database and migrations

```sh
docker compose up -d                                   # start PostgreSQL (dev + test databases)
uv run alembic upgrade head                            # migrate the dev database
uv run alembic revision --autogenerate -m "add users"  # new migration from model changes
uv run alembic downgrade -1                            # undo the last migration
uv run alembic check                                   # fails when models and migrations differ
```

Alembic reads `DATABASE_URL` through `Settings`. The test suite needs no manual migration:
it empties `todolist_test` and migrates it to head at the start of every run.

## Quality checks

All of these must pass before a commit (pytest needs `docker compose up -d`):

```sh
uv run ruff check
uv run ruff format --check
uv run pyright
uv run pytest
```

`uv run ruff format` and `uv run ruff check --fix` fix most style problems.

## Frontend

```sh
npm --prefix frontend install        # once, and after package.json changes
npm --prefix frontend run dev        # Vite on http://localhost:5173, proxies the backend paths to :8000
npm --prefix frontend run build      # type-checks and writes frontend/dist (git-ignored)
npm --prefix frontend run lint       # eslint
npm --prefix frontend run typecheck  # tsc -b --noEmit
npm --prefix frontend run test       # vitest run
npm --prefix frontend run gen:api    # after an API change: frontend/openapi.json + src/api/schema.d.ts
npm --prefix frontend run e2e        # Playwright (Chromium, headless) against the real backend
npx --prefix frontend playwright install chromium   # once per machine, and after a Playwright upgrade
```

`lint`, `typecheck`, `test` and `e2e` must pass before a commit, like the backend checks. With the
dev server, set `PUBLIC_BASE_URL=http://localhost:5173` in `.env`. FastAPI serves `frontend/dist`
itself when it exists at startup (`FRONTEND_DIST`), so `build` + uvicorn is the production setup.

## Conventions

- Configuration comes from environment variables through `todolist.config.Settings`
  (pydantic-settings). Every new setting gets a placeholder line in `.env.example`.
  Never commit secret values; `.env` is git-ignored.
- Build the app with `create_app(settings)`; don't create a module-level `app`.
  Tests pass their own `Settings(_env_file=None, ...)` so a local `.env` can't affect them.
- pyright runs in strict mode on `src/` and standard mode on `tests/`.
- Tests are async (`asyncio_mode = "auto"`): write `async def test_...` and use the
  `client` fixture (httpx `AsyncClient` on the ASGI app) from `tests/conftest.py`.
- The product name lives in `Settings.app_name` only.
- Models subclass `todolist.db.Base` (plus `UUIDPrimaryKeyMixin` / `TimestampMixin`) and their
  module is imported in `src/todolist/models/__init__.py`, otherwise autogenerate misses them.
- Schema changes go through a new Alembic migration; never edit a committed one. Review the
  autogenerated file before committing.
- Routes take the database session as `session: SessionDep` (from `todolist.db`). It is one
  transaction per request: committed when the handler returns, rolled back when it raises.
  Service code calls `session.flush()`, not `session.commit()`.
- Tests that touch the database use the `db_session` fixture. It is the same session the app
  gets through `client`, and everything is rolled back after each test.
- Enum columns use `value_enum(MyStrEnum, "type_name")` from `todolist.db`. Autogenerate does not
  drop the PostgreSQL enum type on downgrade: add `sa.Enum(name="type_name").drop(op.get_bind())`
  to `downgrade()` by hand, and check with `alembic upgrade head && alembic downgrade base`.
- Relationships are `lazy="raise"`; load them with `selectinload(...)` or query explicitly.
- Emails are stored lowercased; look users up with `todolist.models.normalize_email(email)`.
- A new object's `id` is `None` until the first flush. Link new objects through relationships
  (`Membership(organization=org, ...)`) or flush before using the id.
- Routers live in `src/todolist/api/<area>.py` and are included in `api/__init__.py` (prefix `/api`).
  Logic that the MCP tools will share goes in `src/todolist/services/`; routes stay thin.
- Routes that need a signed-in user take `user: CurrentUser` (from `todolist.auth`); settings come
  from `settings: SettingsDep` (from `todolist.config`), never from `get_settings()` in a route.
- Errors: raise `todolist.errors.AppError(status, code, detail)` or a subclass (`NotFoundError`,
  `NotAuthenticatedError`). The body is `{"detail": ..., "code": ...}`. Don't raise `HTTPException`.
- Google login goes through `todolist.google.GoogleClient` (`app.state.google`, `None` when not
  configured). Tests never reach Google: they put a `GoogleClient(..., transport=httpx2.MockTransport(...))`
  on `app.state.google` (see `FakeGoogle` in `tests/test_auth_google.py`).
- Absolute URLs of this app are built from `Settings.public_base_url`, not from the request.
- Tests sign in with `await sign_in(client, email, name)` from `tests/helpers.py`. The test
  settings have `dev_login=True`; a second user in one test needs a second `AsyncClient` on `app`.
- Org-scoped routes (`/api/orgs/{org_id}/...`) take `org: OrgContextDep` (from `todolist.api.deps`):
  it gives `org.organization`, `org.membership`, `org.role` and `org.user`, and answers 404 to
  non-members. Use `org: OrgAdminContextDep` when the action needs an owner or admin (403 for a
  member). Don't compare roles in a route; add a rule function to the service and a dependency.
- 404 means "you can't see it", 403 (`ForbiddenError`) means "you can see it but may not do this".
- A rule that depends on the target (who may remove whom) lives in the service function, which
  raises `ForbiddenError` / `NotFoundError` / `ConflictError(code, detail)` itself (see
  `change_member_role` and `remove_member` in `services/organizations.py`). 409s get a specific code.
- Tests with more users: the `other_client` and `third_client` fixtures (`tests/conftest.py`) and
  `add_member(db_session, org_id, user_id, role)` from `tests/helpers.py`.
- Invitations live in `services/invitations.py`; `get_or_create_user` accepts the pending ones on
  every sign-in. An enum that is a subset of another (`InvitationRole`) gets its own PostgreSQL type.
- Testing a constraint: `begin_nested()` flushes pending objects before the savepoint starts, so add
  the bad row inside it (use `add_in_savepoint` from `tests/helpers.py`).
- The actor type is `todolist.principals.Principal` (kind `user | agent`, id, organization_id, name).
  Permission checks and audit events take a `Principal`; `org.principal` gives the caller's in an
  org-scoped route, `Principal.for_agent(agent)` an agent's.
- A 409 that comes from a unique constraint: make the change and flush inside
  `async with session.begin_nested()` and turn `IntegrityError` into a `ConflictError` (see
  `services/agents.py`). Assign the attributes inside the block: `begin_nested()` flushes first.
- After an UPDATE, `updated_at` is expired; `await session.refresh(obj)` before returning it.
- Project-scoped routes (`/api/projects/{project_id}...`) take `ctx: ProjectContextDep` (viewer or
  higher), `ProjectEditorContextDep` or `ProjectAdminContextDep` (from `todolist.api.deps`, all built
  with `require_project_role(ProjectRole.X)`): 404 `Project not found` without a role, 403 when the
  role is too low. They give `ctx.project`, `ctx.role`, `ctx.user` and `ctx.principal`. A router file
  can export two routers (`org_router` and `router` in `api/projects.py`); include both in
  `api/__init__.py`.
- Permission rules live in `src/todolist/permissions.py` and take a `Principal`:
  `effective_project_role(session, principal, project)`, `role_at_least(role, minimum)` and
  `visible_projects(principal)` (a `select` to filter lists). Add new rules there, not in routes.
- `PrincipalKind` is defined in `models/project_grant.py` (PostgreSQL type `principal_kind`) and
  re-exported by `todolist.principals`. A table that reuses an existing enum type needs
  `postgresql.ENUM(..., create_type=False)` in its migration and must not drop the type on downgrade.
- Tests give a user a project role with `grant_project_role(db_session, project_id, user_id, role)`
  (`tests/helpers.py`); an organization member without a grant sees no project.
- Project grants: `services/project_grants.py` (`list_project_grants`, `set_project_grant`,
  `revoke_project_grant`), routes in `api/project_grants.py`. A principal that may not get a grant
  is a 422 raised as `AppError(422, "invalid_principal", ...)`. List grants (US-014) follow this shape.
- Unpack multi-entity rows directly (`for grant, user, agent in await session.execute(...)`);
  `Result.tuples()` is deprecated in this SQLAlchemy version.
- Lists: model `TodoList` / enum `ListMode` (`models/todo_list.py`), `services/lists.py`
  (`list_lists`, `create_list(session, principal, project, ...)`, `update_list`, `delete_list`,
  `default_list_mode`), routes in `api/lists.py` (`project_router` and `router`).
- List-scoped routes (`/api/lists/{list_id}...`) take `ctx: ListContextDep` (read),
  `ListItemEditorContextDep` (add items), `ListEditorContextDep` (change the list) or
  `ListAdminContextDep` (grants, delete), built with `require_list_action(ListAction.X)`:
  404 `List not found` when the list does not exist for the caller, 403 when the role is too low
  (`forbidden`) or the list mode forbids it (`list_ai_only`). They give `ctx.todo_list`,
  `ctx.project`, `ctx.access`, `ctx.role`, `ctx.user` and `ctx.principal`.
- The one permission check for a list or its items is `list_access(session, principal, todo_list,
  project)` in `permissions.py`: None (404) or a `ListAccess` with `allows(action)` /
  `require(action)` for a `ListAction` (`READ`, `CHANGE_ITEMS`, `EDIT_LIST`, `ADMINISTER`). It
  combines `effective_list_role` with the list mode and the principal kind; don't use
  `effective_list_role` alone to decide access. New list or item operations (also MCP tools) pick
  a `ListAction`; a new kind of operation gets a new member with its rule in `ListAccess.denial`.
- A list created in a test without a mode is `human_only` (the organization has no agent yet), so
  it is invisible to agents: create it with `"mode": "mixed"` or `"ai_only"` for agent tests.
- List grants: model `ListGrant` / enum `ListRole` (`none | viewer | editor | admin`,
  `models/list_grant.py`), `services/list_grants.py` (`list_list_grants`, `set_list_grant`,
  `revoke_list_grant`), routes in `api/list_grants.py`. A list grant replaces the project role on
  that list; organization owners and admins stay admin. `ListRole.project_role` maps to a
  `ProjectRole` (None for `none`).
- Anything that returns several lists filters with `visible_lists(principal, project)` from
  `permissions.py` (`list_lists(session, principal, project)` does). The list index route takes
  `ctx: ProjectListsContextDep`, which also admits a caller with only a list grant.
- Columns that come from an outer join are typed non-optional in a `Row`; `cast` them before an
  `is None` check or pyright (strict) reports an unnecessary comparison.
- Tests give a user a list role with `grant_list_role(db_session, list_id, user_id, ListRole.X)`.
- Items: model `Item` / enum `ItemStatus` (`models/item.py`), `services/items.py` (`list_items`,
  `create_item(session, principal, todo_list, title, notes)`, `update_item(session, principal, item, ...)`,
  `delete_item`), routes in `api/items.py` (`list_router` and `router`). Item-scoped routes
  (`/api/items/{item_id}...`) take `ctx: ItemContextDep` (read) or `ItemEditorContextDep` (change,
  built with `require_item_action`): 404 `Item not found`, 403 as for a list; they give `ctx.item`,
  `ctx.todo_list`, `ctx.project`, `ctx.access`, `ctx.role`, `ctx.user` and `ctx.principal`.
- "Who did it" columns are a `<verb>_by_kind` + `<verb>_by_id` pair without a foreign key (see
  `Item.created_by_*`), filled from a `Principal`.
- Item positions are 1 to n per list (unique constraint `uq_items_list_id_position`, deferred to the
  commit). Anything that changes them takes `_lock_list` first and shifts neighbours with
  `_shift_positions` (`services/items.py`: `create_item`, `move_item`, `delete_item`); never set
  `Item.position` elsewhere. Tests never commit: check a deferred constraint with
  `add_in_savepoint(db_session, obj, check_deferred=True)`.
- A bulk `update(Model)` that must not bump `updated_at` sets `updated_at=Model.updated_at`, and
  uses `.execution_options(synchronize_session="fetch")` so loaded objects get the new values.
- Audit log: model `AuditEvent` / enum `AuditAction` (`models/audit_event.py`), `record_event(session,
  principal, action, *, target_kind, target_id, project_id, list_id, details)` and `changes(old, new)`
  in `services/audit.py`. Every service function that changes a project, list, item or grant takes
  the acting `Principal` and records its event itself, after the change (routes and MCP tools don't).
  A new kind of change gets an `AuditAction` member, an event with the target's name in `details`
  (`changes: {field: {old, new}}` for updates) and a test in `tests/test_audit.py`. No event when
  nothing changed.
- In tests all rows share one `created_at` (one transaction): order events by `AuditEvent.id` (UUIDv7).
- Reading the audit log: `project_events` / `list_events` in `services/audit.py` (an `EventPage` with
  `events` and `next_cursor`, filters in an `EventFilter`), routes in `api/audit.py`
  (`GET /api/projects/{id}/audit`, `GET /api/lists/{id}/audit`, admins only). Another paged list
  follows this shape: keyset on `(created_at, id)`, opaque cursor, `limit` 1 to 200 (default 50).
- Several query parameters: a pydantic model taken as `query: Annotated[MyQuery, Query()]`
  (see `AuditQuery` in `api/audit.py`).
- OAuth server for MCP clients (hand-written, not the SDK's provider; see DECISIONS.md): models in
  `models/oauth.py` (`OAuthClient`, `OAuthAuthorizationRequest`, `OAuthAuthorizationCode`, `OAuthAccessToken`,
  `OAuthRefreshToken`),
  logic in `services/oauth.py`, routes in `api/oauth.py`. Its `root_router` holds the spec-defined
  paths at the app root (`/.well-known/...`, `/register`, `/authorize`, later `/token`, `/revoke`) and
  is included in `app.py`; routes under `/api/oauth/...` go in a normal `router` in the same file.
- Authorization flow: `GET /authorize` validates (`validate_authorization_request`), stores an
  `OAuthAuthorizationRequest` (10 minutes, deleted when answered) and redirects to the SPA page
  `/oauth/consent?request=<id>`, or to `/login?next=/authorize?...` without a session. The consent
  page uses `GET /api/oauth/requests/{id}` and `POST .../approve {agent_id}` / `.../deny`, which
  return `{redirect_url}` (`AppError`s, not `OAuthError`s). Build every authorization response with
  `authorization_response_url(settings, redirect_uri, state, **params)`: it adds `state` and `iss`.
- Who may authorize which agent: `can_authorize_agent` / `authorizable_agents` in `permissions.py`.
- A route that works with and without a session takes `user: OptionalCurrentUser` (`todolist.auth`).
- OAuth endpoints raise `todolist.errors.OAuthError(error, description, status_code=400)` (body
  `{"error", "error_description"}`), not `AppError`. They parse the body themselves so a bad request
  is an OAuth error, not FastAPI's 422.
- OAuth URLs are built from `Settings.oauth_issuer` (no trailing slash) and `Settings.mcp_resource_url`.
  Build the SDK's metadata models with `Model.model_validate({... strings ...})`: `AnyHttpUrl("http://host")`
  adds a trailing slash, and clients compare the issuer as a string.
- Codes and tokens: `new_token()` gives the plain value, `hash_token()` what is stored and looked up
  (`services/oauth.py`). Never store or log the plain value. The only scope is `MCP_SCOPE` (`mcp`).
- Tokens: `services/oauth_tokens.py` (`token_request`, `revoke_token`, `resolve_access_token(session, token)`,
  which gives the agent `Principal` or None), routes `POST /token` and `POST /revoke`. They take a
  form body (`parse_form`); clients are public and identified by the `client_id` field. Every token
  check goes through `_authorized_agent`: a token is dead when the approving user may no longer
  authorize the agent.
- A request's transaction is rolled back when the handler raises. An error that must keep its
  changes (revoking tokens after a replayed code: `ReplayedGrantError`) is caught in the route and
  returned with `oauth_error_response(error)` from `todolist.errors`.
- Look a client up with `find_client(session, client_id)` (`services/oauth.py`), not `session.get`:
  the id comes from the request and PostgreSQL rejects a NUL byte in a text parameter.
- In a test, change a loaded row by setting the attribute and flushing (`row.expires_at = ...`);
  a bulk `update()` leaves the objects already in the shared session stale.
- For anything about MCP or its OAuth flow, read the installed SDK (`.venv/lib/python3.14/site-packages/mcp/`,
  version 2.x: `MCPServer`, `mcp.server.auth`, `mcp.client.auth`) and the spec revision 2026-07-28
  (`https://modelcontextprotocol.io/specification/latest/basic/authorization`) instead of memory.
- MCP server: `src/todolist/mcp_server/` (`server.py` builds the SDK `MCPServer` per app, stateless
  streamable HTTP with JSON responses; `context.py` the bearer check and `agent_context`; `tools.py`
  the tools). `create_app` routes `/mcp` to it and runs its session manager in the lifespan.
- A new MCP tool goes in `register_tools(server, agent_context)` (`mcp_server/tools.py`):
  `@server.tool()` on an `async def` with a docstring (the description agents see) that returns a
  pydantic model, and inside it `async with agent_context() as ctx:` for `ctx.principal` (the agent)
  and `ctx.session` (one transaction per call, committed at the end of the block). Call the service
  functions with `ctx.principal`; permission checks go through `permissions.py` as in the routes.
- Code outside a route opens a session with `app.state.session_scope()` (`todolist.db.transaction`);
  the `app` fixture replaces it with the test's `db_session`.
- Lists across all projects of a principal's organization: `accessible_lists(principal)` in
  `permissions.py` (`visible_lists(principal, project)` is that, narrowed to one project).
- MCP tests (`tests/test_mcp.py`): `agent_token(client)` gives `(Authorized, token)`, and
  `async with mcp_client(app, token) as mcp:` the SDK client on the ASGI app (`await mcp.call_tool(...)`,
  `result.structured_content`). It runs the app lifespan (`running(app)`); enter it in the test body,
  never in a fixture (the task group must start and stop in the same task). Raw requests:
  `mcp_http(app, token)`, an `httpx2` client on `http://localhost:8000` (the only allowed `Host`).
  Give the agent a list with `grant_agent(db_session, list_id, agent_id, ListRole.X)` on a `mixed` list.
- MCP tool errors: raise an `AppError` (`NotFoundError`, `ForbiddenError`, `access.require(action)`)
  inside `agent_context()`; it becomes the SDK's `ToolError` with the error's `detail`, which the
  agent reads as `Error executing tool <name>: <detail>`. Write the detail for a model (say what to
  call instead). Load a list in a tool with `_accessible_list(ctx, list_id, ListAction.X)`
  (`mcp_server/tools.py`): the list, its project and the `ListAccess`, or the not-found error.
- MCP tools return a pydantic model with a named array (`ListList(lists=[...])`), never a bare list;
  parameters are `Annotated[uuid.UUID, Field(description=...)]`.
- Read helpers for the tools: `list_accessible_lists(session, principal, project=None)`
  (`services/lists.py`, lists with their project), `count_items(session, list_ids)` and
  `list_items(session, todo_list, include_done=...)` (`services/items.py`),
  `list_projects_with_lists` (`services/projects.py`, on `projects_with_accessible_lists`).
- MCP tool tests: `call(mcp, tool, **arguments)` and `error_of(mcp, tool, **arguments)` in
  `tests/test_mcp_read_tools.py`, with `grant_agent_project`, `add_list`, `add_item`, `project_of`.
- MCP write tools (`add_item`, `update_item`, `complete_item`, `reopen_item`, `move_item`,
  `delete_item` in `mcp_server/tools.py`): load the item with `_accessible_item(ctx, item_id,
  ListAction.CHANGE_ITEMS)` and call the item service. A tool whose name is also an imported service
  function is defined as `<name>_tool` with `@server.tool(name="<name>")`. Return `_changed_item(item)`.
- `ItemTitle` / `ItemNotes` (the accepted title and notes) live in `services/items.py`; the API
  models and the MCP tool parameters both use them. In a tool, an optional text that can be removed
  is removed with an empty string (a left-out argument and null look the same).
- MCP write-tool tests: `tests/test_mcp_write_tools.py` (`shared_list(client, db_session, role, mode)`
  gives `(authorized, token, list_id)`, `events_since`, `assert_by_agent`).

- The end-to-end onboarding test is `tests/test_mcp_oauth_e2e.py`: the SDK's `OAuthClientProvider`
  as `auth` on the `mcp_http` client, with a `Browser` (the user's `client`) as its redirect and
  callback handlers. A change to the OAuth endpoints, the consent API or the /mcp challenge must
  keep it passing; extend it rather than adding a second full-flow test.
- Frontend layout: `frontend/src/main.tsx` (the `BrowserRouter`), `App.tsx` (the `<Routes>`; tests
  render it in a `MemoryRouter`), `pages/<Name>Page.tsx`, `config.ts` (`APP_NAME`, the only place
  with the product name in the frontend), tests next to the code as `*.test.tsx`. Import from
  `react-router` (v8; there is no `react-router-dom`). Tailwind 4 has no config file: it is the
  `@tailwindcss/vite` plugin plus `@import 'tailwindcss'` in `src/index.css`.
- Frontend tests: vitest without globals (`import { expect, test } from 'vitest'`), jsdom, Testing
  Library with the jest-dom matchers (`src/test/setup.ts`). The vitest config is in `vite.config.ts`.
- TypeScript stays on 6.0 until typescript-eslint supports 7 (its peer range ends below 6.1).
- Paths the backend owns are listed twice and must stay equal: `BACKEND_PATHS` in
  `frontend/src/backendPaths.ts` (the dev proxy in `vite.config.ts`, and `isBackendPath`) and
  `BACKEND_PREFIXES` in `src/todolist/frontend.py` (what the SPA fallback never answers). A new
  backend path outside `/api` goes in both.
- `install_frontend(app, settings.frontend_dist)` (`src/todolist/frontend.py`) is the last route of
  `create_app`: GET/HEAD outside the backend paths get a file of the build or `index.html`. The test
  settings have `frontend_dist=None`; a test that wants a build overrides the `settings` fixture
  (see `tests/test_frontend.py`).
- API types: `npm --prefix frontend run gen:api` writes `frontend/openapi.json` (from
  `python -m todolist.openapi`) and `frontend/src/api/schema.d.ts` (openapi-typescript); both are
  committed, never edited by hand. Run it after every change to a route or an API model:
  `tests/test_openapi.py` fails when the saved schema is behind.
- Frontend API calls: `unwrap(api.GET('/api/...', { params, body }))` from `src/api/client.ts`
  (openapi-fetch on the generated `paths`): the body, or a thrown `ApiError` (`status`, `code`,
  `message` = the backend's `detail`). Body types: `Schemas['MeOut']`. Use it inside TanStack Query
  hooks (`useQuery` / `useMutation`); the client comes from `createQueryClient()`
  (`src/api/queryClient.ts`), which also signs the user out of the UI on any 401.
- Frontend auth: `src/auth/hooks.ts` (`useMe` (data null = signed out), `useAppConfig`,
  `useDevLogin`, `useSignOut`), `src/auth/RequireAuth.tsx` (the guard: every route except `/login`
  goes inside it in `App.tsx`, within `AppLayout`), `src/auth/next.ts` (`safeNextPath`, `loginPath`,
