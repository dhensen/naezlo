# Ralph Progress Log

## Codebase Patterns

(Reusable patterns go here. Keep this section short and current.)

- Stack and domain rules: see DECISIONS.md.
- There is no git remote named origin: commit, don't push.
- pnpm is not installed; use npm for the frontend.
- Commands and conventions: root CLAUDE.md. App is built with `create_app(settings)`; tests use the `settings`, `app` and `client` fixtures in tests/conftest.py.
- Postgres: `docker compose up -d` (host port 5435, databases todolist and todolist_test).
  Other projects' Postgres containers run on 5432-5434 on this machine; leave them alone.
- DB in routes: `session: SessionDep` (todolist.db); commit/rollback is done by the dependency,
  services only `flush()`. DB in tests: `db_session` fixture (same session the `client` app uses,
  rolled back after each test; `commit()` inside it is only a savepoint release).
- New model: subclass `Base` + `UUIDPrimaryKeyMixin` + `TimestampMixin`, import the module in
  src/todolist/models/__init__.py, then `uv run alembic revision --autogenerate -m "..."` and
  `uv run alembic upgrade head` (dev DB). Tests re-migrate todolist_test themselves.
- Enum column: `value_enum(MyStrEnum, "pg_type_name")` (todolist.db). Add
  `sa.Enum(name="pg_type_name").drop(op.get_bind())` to the migration's downgrade by hand.
- Relationships are `lazy="raise"`: use `selectinload` or a join. Emails: `normalize_email()`.
- Signed-in user in a route: `user: CurrentUser` (todolist.auth). Settings: `settings: SettingsDep`.
  Errors: raise `AppError` / `NotFoundError` (todolist.errors), body `{"detail", "code"}`.
- Routers: src/todolist/api/<area>.py, included in api/__init__.py. Shared logic: src/todolist/services/.
- Tests sign in with `await sign_in(client, email, name)` (tests/helpers.py, uses dev-login, returns
  the /api/me body). For a second user in one test, open another `AsyncClient` on the `app` fixture.
- `obj.id` is None until the first flush: link new rows through relationships or flush first.
- New organization: `create_organization(session, name, owner)` (services/organizations.py) gives
  it a unique slug and an owner membership.
- Outbound HTTP uses `httpx2` (Authlib needs it); the test client is still `httpx`. Mock outbound
  calls with `httpx2.MockTransport`. Google login tests: `FakeGoogle` in tests/test_auth_google.py.
- `Settings.public_base_url` (PUBLIC_BASE_URL) exists since US-005; build absolute URLs from it.
- Routes opened by browser navigation redirect to `/login?error=<code>` instead of returning JSON.
- Org-scoped route: `org: OrgContextDep` (todolist.api.deps; 404 for non-members) or
  `org: OrgAdminContextDep` (also 403 unless owner/admin). Role rule: `can_manage_organization`.
- More users in a test: `other_client` / `third_client` fixtures (tests/conftest.py) and
  `add_member(db_session, org_id, user_id, role)` (tests/helpers.py).
- Rules that depend on the target live in the service, which raises ForbiddenError / NotFoundError /
  `ConflictError(code, detail)` itself (see `change_member_role`, `remove_member`).
- Testing a constraint: add the bad row and flush, both inside `async with session.begin_nested()`
  (`add_in_savepoint` in tests/helpers.py), under `pytest.raises(IntegrityError)`. Adding
  before `begin_nested()` fails outside the savepoint and leaves the session unusable.
- Invitations: services/invitations.py (`invite`, `list_invitations`, `revoke_invitation`,
  `accept_pending_invitations`, called by `get_or_create_user` on every sign-in).
- Actor type: `Principal` (todolist.principals; kind user | agent, id, organization_id, name).
  `org.principal` in org-scoped routes, `Principal.for_agent(agent)` for agents. Agents:
  services/agents.py (`list_agents`, `get_agent`, `create_agent`, `update_agent`, `delete_agent`).
- 409 from a unique constraint: change + flush inside `async with session.begin_nested()`, catch
  `IntegrityError`, raise `ConflictError` (services/agents.py). Assignments go inside the block.
- A PATCH that returns `updated_at` needs `await session.refresh(obj)` after the flush.
- Projects: services/projects.py (`list_projects(session, principal)`, `create_project` (adds the
  creator's admin grant), `update_project`, `delete_project`).
- Permissions: src/todolist/permissions.py (`effective_project_role(session, principal, project)`,
  `role_at_least`, `visible_projects(principal)`). Project-scoped route
  (`/api/projects/{project_id}...`): `ctx: ProjectContextDep` (viewer), `ProjectEditorContextDep` or
  `ProjectAdminContextDep` from todolist.api.deps, all made by `require_project_role(ProjectRole.X)`:
  404 without a role, 403 when the role is too low; `ctx.project`, `ctx.role`, `ctx.user`,
  `ctx.principal`. For another minimum or a nested resource, wrap `require_project_role(...)` in
  `Annotated[ProjectContext, Depends(...)]`.
- Tests: `grant_project_role(db_session, project_id, user_id, role)` (tests/helpers.py). A plain
  organization member sees no project without a grant.
- Project grants: services/project_grants.py (`list_project_grants`, `set_project_grant` (create or
  update, 422 `invalid_principal`), `revoke_project_grant`); API `GET|PUT /api/projects/{id}/grants`,
  `DELETE .../grants/{grant_id}`. In tests, share a project through the API with
  `client.put(grants_url, json={"principal_kind", "principal_id", "role"})`.
- Lists: models/todo_list.py (`TodoList`, `ListMode`), services/lists.py (`list_lists`,
  `create_list(session, principal, project, name, description, mode=None)`, `update_list`,
  `delete_list`, `default_list_mode`), api/lists.py. List-scoped route (`/api/lists/{list_id}...`):
  `ctx: ListContextDep` / `ListEditorContextDep` / `ListAdminContextDep` (todolist.api.deps, made by
  `require_list_role`): `ctx.todo_list`, `ctx.project`, `ctx.role`, `ctx.user`, `ctx.principal`.
  The rule is `effective_list_role(session, principal, todo_list, project)` in permissions.py.
- List grants: models/list_grant.py (`ListGrant`, `ListRole` with `none`), services/list_grants.py,
  api/list_grants.py (`/api/lists/{id}/grants`, list admin). A list grant beats the project role
  (not organization owners/admins). Several lists at once: `visible_lists(principal, project)`
  (permissions.py); `list_lists(session, principal, project)` uses it. Tests:
  `grant_list_role(db_session, list_id, user_id, ListRole.X)`. The list shape has `project_name`.
- Items: models/item.py (`Item`, `ItemStatus`), services/items.py (`list_items`, `create_item`,
  `update_item`, `delete_item`; the changing ones take a `Principal`), api/items.py. Item-scoped
  route (`/api/items/{item_id}...`): `ctx: ItemContextDep` / `ItemEditorContextDep` (made by
  `require_item_role`): `ctx.item`, `ctx.todo_list`, `ctx.project`, `ctx.role`, `ctx.principal`.
- Item order: positions are 1..n per list, unique in the database (deferred constraint).
  `move_item(session, principal, item, before_item_id)`; create, move and delete lock the list row
  (`_lock_list`) and shift with `_shift_positions`. API `POST /api/items/{id}/move`. Tests that
  import helpers from another test module (`from tests.test_items import ada_list, create, join`) work.
  Actor columns are `<verb>_by_kind` + `<verb>_by_id` without a foreign key.
- Member removal must delete every kind of grant in the organization (`remove_member` in
  services/organizations.py); extend it when a new grant table appears.

---
- Access to a list or its items: `list_access(session, principal, todo_list, project)`
  (permissions.py) gives None (404) or a `ListAccess`; `access.require(ListAction.X)` raises the
  403 (`forbidden` or `list_ai_only`). It includes the list mode. Don't decide on
  `effective_list_role` alone. A list made in a test without a mode is human_only: no agent sees it.
