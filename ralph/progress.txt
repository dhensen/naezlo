# Ralph Progress Log

## Codebase Patterns

(Reusable patterns go here. Keep this section short and current.)

- Stack and domain rules: see DECISIONS.md.
- There is no git remote named origin: commit, don't push.
- pnpm is not installed; use npm for the frontend.
- Commands and conventions: root CLAUDE.md. App is built with `create_app(settings)`; tests use the `settings`, `app` and `client` fixtures in tests/conftest.py.
- Postgres: `docker compose up -d` (host port 5435, databases todolist and todolist_test).
  Other projects' Postgres containers run on 5432-5434 on this machine; leave them alone.
- DB in routes: `session: SessionDep` (todolist.db); commit/rollback is done by the dependency,
  services only `flush()`. DB in tests: `db_session` fixture (same session the `client` app uses,
  rolled back after each test; `commit()` inside it is only a savepoint release).
- New model: subclass `Base` + `UUIDPrimaryKeyMixin` + `TimestampMixin`, import the module in
  src/todolist/models/__init__.py, then `uv run alembic revision --autogenerate -m "..."` and
  `uv run alembic upgrade head` (dev DB). Tests re-migrate todolist_test themselves.
- Enum column: `value_enum(MyStrEnum, "pg_type_name")` (todolist.db). Add
  `sa.Enum(name="pg_type_name").drop(op.get_bind())` to the migration's downgrade by hand.
- Relationships are `lazy="raise"`: use `selectinload` or a join. Emails: `normalize_email()`.
- Signed-in user in a route: `user: CurrentUser` (todolist.auth). Settings: `settings: SettingsDep`.
  Errors: raise `AppError` / `NotFoundError` (todolist.errors), body `{"detail", "code"}`.
- Routers: src/todolist/api/<area>.py, included in api/__init__.py. Shared logic: src/todolist/services/.
- Tests sign in with `await sign_in(client, email, name)` (tests/helpers.py, uses dev-login, returns
  the /api/me body). For a second user in one test, open another `AsyncClient` on the `app` fixture.
- `obj.id` is None until the first flush: link new rows through relationships or flush first.
- New organization: `create_organization(session, name, owner)` (services/organizations.py) gives
  it a unique slug and an owner membership.
- Outbound HTTP uses `httpx2` (Authlib needs it); the test client is still `httpx`. Mock outbound
  calls with `httpx2.MockTransport`. Google login tests: `FakeGoogle` in tests/test_auth_google.py.
- `Settings.public_base_url` (PUBLIC_BASE_URL) exists since US-005; build absolute URLs from it.
- Routes opened by browser navigation redirect to `/login?error=<code>` instead of returning JSON.
- Org-scoped route: `org: OrgContextDep` (todolist.api.deps; 404 for non-members) or
  `org: OrgAdminContextDep` (also 403 unless owner/admin). Role rule: `can_manage_organization`.
- More users in a test: `other_client` / `third_client` fixtures (tests/conftest.py) and
  `add_member(db_session, org_id, user_id, role)` (tests/helpers.py).
- Rules that depend on the target live in the service, which raises ForbiddenError / NotFoundError /
  `ConflictError(code, detail)` itself (see `change_member_role`, `remove_member`).
- Testing a constraint: add the bad row and flush, both inside `async with session.begin_nested()`
  (`add_in_savepoint` in tests/test_invitations.py), under `pytest.raises(IntegrityError)`. Adding
  before `begin_nested()` fails outside the savepoint and leaves the session unusable.
- Invitations: services/invitations.py (`invite`, `list_invitations`, `revoke_invitation`,
  `accept_pending_invitations`, called by `get_or_create_user` on every sign-in).

  - The login redirect's query string holds `state` and `nonce`; a test must copy the nonce into
    the fake ID token or validation fails.
  - The frontend login page (US-028) should link to `/api/auth/google/login?next=<path>` and show
